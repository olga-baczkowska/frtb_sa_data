# Synthetic FRTB SA equity portfolio — movement-explain test dataset

24 monthly snapshots (2024-07-31 … 2026-06-30) of trade-level FRTB SA
equity sensitivities, generated by `generate.py` (seed fixed: fully
reproducible).

## Files

Per date, three sensitivity files:

| File pattern | RiskType | Rows/date (approx) | Granularity |
|---|---|---|---|
| `EQUITY_EQDELTA_{date}` | EQDELTA | 8,200–9,900 | trade x underlying, BucketCode `["SINGLE"]` |
| `EQUITY_EQVEGA_{date}` | EQVEGA | 7,200–9,600 | trade x underlying, 5-tenor lists `[0.5Y,1Y,3Y,5Y,10Y]` |
| `EQUITY_EQGAMMA_{date}` | EQGAMMA | 6,500–8,600 | trade x underlying, curvature: `SHIFTUPPNL`, `SHIFTDOWNPNL`, `CURVDELTA`, `CurvatureFlag='Y'` |

Reference extras (for validating agent narratives against ground truth):

- `REF_TRADES` — full trade store: type, underlying, inception/maturity,
  strike, barrier, variance strike, signed notional (24,977 trades ever booked)
- `REF_MARKET_DATA` — spot + 5-pillar vol per underlying per date
- `REF_UNIVERSE` — 200 underlyings: bucket, region, ccy, rate, dividend yield
- `REF_RUN_SUMMARY` — per-date live-trade counts, expiries, knockouts,
  net/gross delta and vega

Format: `csv.gz` here (parquet writer unavailable in the generation
sandbox); run `python convert_to_parquet.py output output_parquet` to get
parquet with the list columns (`BucketCode`, `RiskValue`, `RWLavel`)
restored as native lists. `generate.py` itself writes parquet directly
when pyarrow is importable.

## Portfolio

- ~10,800 seasoned trades at t0, ~520 new trades/month, expiry on maturity,
  barrier knockout on monthly observation dates → live book 9,100–11,000.
- 200 underlyings: 12 developed-market indices, ~150 G7 large caps (US-heavy),
  12 EM large caps, 36 small caps; buckets 1–10 populated (indices mapped into
  advanced large-cap buckets 5–8 as a simplification since the spec caps
  buckets at 10; real FRTB would use buckets 12/13).
- Trade types: FORWARD, EURO_CALL/PUT, STRADDLE, DIGITAL_CALL/PUT,
  BARRIER_UO_CALL, BARRIER_DO_PUT, VAR_SWAP. All closed-form
  (Black-Scholes; Reiner-Rubinstein barriers, MC-validated; simplified
  implied-variance mark for var swaps — realised leg ignored).
- Per-underlying delta-hedge forwards booked at inception (85% hedge ratio):
  net delta runs at ~0.5–3% of gross delta while gamma/vega stay material.
- Long/short ≈ 50/50; moneyness lognormal around ATM, wider at long tenors;
  tenors 3M–10Y skewed short so expiries occur throughout the window.

## Market model

- Spots: correlated monthly GBM — global factor + region factor + idio.
- Vols: per-name short vol is a mean-reverting log-OU process, correlation
  −0.55 with own return; pillar term structure blends short vol into a
  long-run level. Flat smile (term structure only).
- **Engineered regime event at 2025-09-30**: ~−8% global-factor shock plus a
  vol spike → visible in gross vega (+17%), a knockout cluster (47 barrier
  KOs), and a gross-delta drop. Useful as a known-answer test for the
  movement-explain agent.

## Sensitivity conventions (confirmed 2026-07-12)

- `EQDELTA.RiskValue = (V(1.01·S) − V(S)) / 0.01` (MAR21.19-style 1%
  relative shift, annualised to full relative move).
- `EQVEGA.RiskValue = σ · ∂V/∂σ` (central FD), allocated to the two
  adjacent tenor pillars by linear interpolation in remaining maturity.
- `EQGAMMA`: `SHIFTUPPNL = V(S(1+RW)) − V(S)`, `SHIFTDOWNPNL = V(S(1−RW)) − V(S)`
  with CRR2 bucket spot risk weights
  {1:55, 2:60, 3:45, 4:55, 5:30, 6:35, 7:40, 8:50, 9:70, 10:50}%;
  `CURVDELTA = RW × delta_sensitivity`; `RiskValue = SHIFTUPPNL + SHIFTDOWNPNL`
  (convexity proxy). CVR± can be assembled downstream as
  `−(SHIFT{UP,DOWN}PNL ∓ CURVDELTA)`.

## Spec deviations / assumptions (confirmed 2026-07-12)

1. The four output blocks in the spec had crossed labels (e.g. the block
   headed "EQVEGA" carried EQGAMMA fields). Implemented as three risk types:
   EQDELTA, EQVEGA, EQGAMMA-with-curvature.
2. `RWLavel` spelling kept verbatim from the spec.
3. Vega `RWLavel` built as `{bucket}_{tenor}_SPOT` (e.g. `5_1Y_SPOT`);
   literal concatenation per the spec would give `51Y_SPOT`.
4. All rows carry `BusinessLine='GLOBAL EQUITIES'`, `DeskName='EQUITY
   DERIVATIVES'` — equity risk logically sits on the equity desk. If you
   want cross-desk attribution scenarios, split the book in `build_outputs`.
5. `GroupId` = 1-based row order within each file.
6. Delta rows also carry `BucketCode`/`RiskValue` as single-element lists,
   mirroring the vega layout, per the bracketed notation in the spec.

# FX asset class extension (EUR reporting currency)

24 monthly snapshots of trade-level FX sensitivities, generated by
`generate_fx.py` (reuses the equity pricing machinery via Garman-Kohlhagen:
S = EUR value of 1 unit of foreign ccy, r = EUR rate 2.5%, q = foreign rate).

## Files per date

| File pattern | RiskType | Notes |
|---|---|---|
| `FX_FXDELTA_{date}` | FXDELTA | RiskFactor = `{FRTBBucket}` (e.g. `USDEUR`), scalar RWLabel |
| `FX_FXVEGA_{date}` | FXVEGA | 5-tenor lists; RWLabel list `{label}_{tenor}` |
| `FX_FXGAMMA_{date}` | FXGAMMA | + `CurvatureFlag='Y'`, `FXDivisorEligibility='N'`, SHIFT PnLs, CURVDELTA; RiskFactor = `{Underlying}` |

References: `REF_FX_TRADES`, `REF_FX_MARKET_DATA` (spot + 5-pillar vol per
pair), `REF_FX_UNIVERSE`, `REF_FX_RUN_SUMMARY`.

## Portfolio & market

- 29 currency pairs vs EUR: 19 CRR liquid (`FXLiquidCCY`), 2 ERM-II pegged
  (`DKKEUR`, `BGNEUR` labels), 8 other (`FXUnderlying`: PLN, CZK, HUF, RON,
  ILS, THB, IDR, CLP). HRK label supported in code, no trades (euro adopted
  2023).
- ~12,000 seasoned trades at t0, ~900 new/month; live book 7,800-12,000
  (FX tenors run shorter than equity, hence higher turnover). Forward-heavy
  mix (30%) plus vanillas, straddles, digitals, barriers (vol-scaled barrier
  distances), small var-swap sleeve. Pegged pairs trade forwards only.
- Spots: risk-on/off factor model - USD-bloc & JPY/CHF appreciate vs EUR in
  risk-off while EM/CEE depreciate; pegged pairs mean-revert tightly to peg.
  Vol: log-OU per pair, positively correlated with the risk-off factor.
- **Same engineered regime event at 2025-09-30** as equity: risk-off shock
  (USD +7%, TRY -19% type moves) + vol spike -> gross vega +63%
  (1.88e9 -> 3.08e9), decaying over subsequent months. Cross-asset-consistent
  with the equity stress: a combined-book movement-explain run should
  attribute both to the same event.

## FX spec deviations / assumptions (confirmed 2026-07-12)

1. `FRTBBucket`: delta block says "ccy bucket", gamma/vega blocks say
   "int 1 to 10" (equity leftover - FX has no 1-10 enumeration). Used the
   pair code `{CCY}EUR` consistently in all three files.
2. Third block headed "EQVEGA" but `RiskType = FXVEGA` -> FXVEGA;
   `RiskValue` emitted as 5-element list aligned to BucketCode (spec's
   scalar "sensitivity" contradicts the tenor list).
3. `RWLabel` spelled as in the FX spec (the equity files keep `RWLavel`).
4. Vega RWLabel built as `{label}_{tenor}` (e.g. `FXLiquidCCY_1Y`,
   `DKKEUR_3Y`).
5. Curvature shocks: 15% for all pairs (consistent with
   `FXDivisorEligibility='N'`, i.e. no sqrt(2) divisor applied), 2.25% for
   DKK/BGN (ERM-II band assumption). Delta RWs are left to the downstream
   engine via RWLabel.
6. RiskFactor granularity differs by design of the spec: `USDEUR` in delta
   vs `USD` in vega/gamma - joins across risk types should key on
   Underlying or TradeId, not RiskFactor.
7. All rows: `BusinessLine='GLOBAL FX'`, `DeskName='FX CASH'` (only desk
   available for that business line in the spec).
8. FX exposure embedded in the equity book (non-EUR equity PVs) is NOT
   cross-populated into the FX files - the two asset classes are independent
   trade populations.

# GIRR asset class extension (EUR reporting currency)

24 monthly snapshots of trade-level GIRR sensitivities, generated by
`generate_girr.py`.

## Files per date

| File pattern | RiskType | Notes |
|---|---|---|
| `GIRR_IRDELTA_{date}` | IRDELTA | 10-tenor lists [0.25Y..30Y]; Underlying = curve name, RiskFactor = `{Underlying}_YIELD` |
| `GIRR_IRVEGA_{date}` | IRVEGA | 25-element lists over BucketCode x BucketCode2 (option expiry x underlying swap tenor), row-major bc1-outer; RWLabel `GIRRUnderlying_{bc1}_{bc2}`; RiskFactor `{Underlying}:YIELD` |
| `GIRR_IRGAMMA_{date}` | IRGAMMA | parallel-shift curvature per ccy; `CurvatureFlag='Y'`, `FXDivisorEligibility='N'`; Underlying = ccy |

References: `REF_GIRR_TRADES`, `REF_GIRR_MARKET_DATA` (zero curves on 10
pillars + swaption ATM vols on 5 expiry pillars), `REF_GIRR_UNIVERSE`,
`REF_GIRR_RUN_SUMMARY`.

## Portfolio & market

- 14 currencies / 16 curves (EUR: ESTER + EURIBOR-3M basis; USD: SOFR +
  legacy LIBOR-3M basis; others one curve each). FRTBBucket = ccy.
- Instruments: SWAP (signed payer/receiver), FRA, BOND, PAYER/RECEIVER
  swaptions (Black on the forward swap rate; cash-settled at expiry -
  no exercise into swap). Single-curve pricing per trade, annual fixed
  schedules; strikes jittered around par/forward for seasoned realism.
- ~10,200 seasoned trades at t0; monthly new business ~280 with a
  swaption-skewed mix (60% options) so the vega sleeve stays ~2,600 trades
  against its faster expiry cycle. Live book 8,700-10,300.
- Per-curve par-swap delta hedges at inception (85%): net parallel delta
  ~0.5-1.5% of gross.
- Curve dynamics: level/slope/curvature factors on zero rates, global level
  factor across ccys; OU basis spreads between same-ccy curves.
- **Same 2025-09-30 regime event**: bull steepener in majors (EUR -78bp
  front / -55bp 10Y), CEE risk-premium divergence (PLN +92bp), swaption vol
  spike -> gross vega +31%, gross delta +6%. Third asset class consistent
  with the equity/FX stress: cross-asset attribution should identify one
  event, including the sign-divergent CEE rates move.

## GIRR spec deviations / assumptions (confirmed pattern, review)

1. Blocks 2/3 headed RiskClass "IR" but field says "GIRR" -> GIRR
   everywhere; gamma `RiskType="FXGAMMA"` -> IRGAMMA.
2. Underlying stored WITHOUT the `_YIELD` suffix
   (`IR-SWAP-EUR-ESTER-1D-ON_EUR`); RiskFactor appends `_YIELD`, matching
   the spec's example strings exactly.
3. RWLabel liquidity mapping keys off the FX pair list ({ccy}EUR in the
   liquid 19 -> `GIRRLiquidCCY...`, else `GIRRUnderlying...`); EUR
   special-cased to liquid (reporting ccy, sqrt(2) divisor under CRR).
   DKK/PLN/CZK/HUF fall to `GIRRUnderlying`.
4. Vega RWLabel is the fixed `GIRRUnderlying_{bc1}_{bc2}` per the literal
   spec (no liquidity split - FRTB vega RW is uniform anyway). Vega
   Underlying = curve name (spec's "underlying ID" read as the delta
   convention).
5. Gamma: spec omits BucketCode; emitted `BucketCode=["SINGLE"]` and
   RiskValue as single-element list for cross-class consistency. Curvature
   = parallel shift of the trade's curve at RW 1.7% (/sqrt(2) if liquid);
   swaptions only, consistent with EQ/FX (linear trades excluded).
6. DeskName: linear trades -> FLOW RATES G10, swaptions -> STRUCTURED
   RATES (both under GLOBAL DEBT MARKETS) - gives desk-level attribution
   variety; note CEE-currency linear trades also sit on FLOW RATES G10 as
   the only rates desk available.
7. IRDELTA rows include all trades; no cross-population of IR discounting
   risk from the EQ/FX books (independent trade populations, as before).

# CSR NON-SEC + DRC NON-SEC extension

24 monthly snapshots generated by `generate_csr.py`. Credit book ~2,300-2,400
live trades over 63 curves: 53 single names (6 sovereigns, 3 local
governments, corporates by sector, 3 covered-bond issuers), 5 CDS indices
(iTraxx Main/Crossover/Senior Financials S41, CDX IG/HY S42).

## Files per date

| File pattern | RiskType | Notes |
|---|---|---|
| `CSRNONSEC_CS01_{date}` | CS01 | 5-tenor lists; RWLabel `{bucket}_{rating}` repeated per tenor (per spec); RiskFactor `{Underlying}:CDS|BOND` |
| `CSRNONSEC_CRVEGA_{date}` | CRVEGA | index options only, expiry-pillar allocation; RWLabel `{bucket}_{tenor}` |
| `CSRNONSEC_CSRGAMMA_{date}` | CSRGAMMA | options only; relative spread shock s*(1+/-RW_bucket); CurvatureFlag/FXDivisorEligibility |
| `DRCNONSEC_JTD_{date}` | JTD | credit book + EQUITY book cross-populated; ~10,500 rows/date |

References: `REF_CSR_TRADES`, `REF_CSR_MARKET_DATA` (5-pillar spreads +
index option vols + rating per name per date), `REF_CSR_UNIVERSE`,
`REF_CSR_RUN_SUMMARY`.

## Known-answer events

- **Rating migrations** (bucket, rating, RWLabel AND the Underlying's
  `_{bucket}` suffix all change while the trade population does not):
  BAYER BBB->BB at 2025-05-31 (7->15, spread x1.9); RENAULT BB->BBB at
  2025-07-31 (13->5, x0.65); GLENCORE BBB->BB at 2025-11-30 (4->12, x1.8).
- **Same 2025-09-30 stress**: spreads widen (iTraxx Main +63%, HY +45% log),
  index option vol spike (0.62->1.35). Note gross CS01 correctly FALLS
  slightly at the stress - RPV01 shortens as hazard rises; a movement-explain
  narrative that reads falling gross CS01 as de-risking would be wrong, which
  makes this a deliberately adversarial test case.

## CSR/DRC spec deviations / assumptions (review)

1. `RiskClass "CSR NON-SECFRTBB"` -> "CSR NON-SEC"; block 3 headed IRVEGA
   with `RiskType=CRVEGA` -> CRVEGA.
2. Buckets: 1-16 single names (Basel sector x IG/HY), 17 other (unused),
   **19 = IG indices, 20 = HY indices** - decoded from the spec example's
   `_19` suffix on an IG financials index; bucket 18 unused.
3. Underlying carries `_{bucket}` suffix in all CSR files (per the example);
   bonds keyed by synthetic ISIN, CDS/options by curve name. DRC Underlying
   and ObligorId carry `_{DRC bucket name}` suffixes.
4. Curvature: relative spread shock at approximate Basel CSR delta RWs per
   bucket (table in code); options only, consistent with other classes.
5. CRVEGA Underlying = index curve name (single-name CDS options have no
   liquid market); RiskValue allocated over option-expiry pillars.
6. DRC JTD conventions: bonds LGD*Ntl + (V - Ntl); CDS bought-protection
   -LGD*Ntl + V; equity V - V(S->0) full-reval default P&L; LGDs covered
   25% / senior 75% / sub 100%; ScaledGrossJTD = JTD * clip(T, 0.25, 1.0).
   Index CDS kept at index-obligor level (no constituent decomposition);
   index options and equity var swaps excluded from DRC.
7. Equity DRC ratings assigned synthetically (indices BBB; small caps BB/B;
   large caps AA/A/BBB); equity forwards ShareType=FUTURES, indices
   EQINDEX, single names EQSHR.
8. Pricing simplifications: flat EUR discounting (no GIRR cross-population),
   flat recovery 0.40 in hazard conversion, index option forward spread
   proxied by the 5Y pillar.

# Formatting revision (2026-07-14)

Applied to all shipped files and to the generators (reruns produce the
corrected formats natively):

- `GroupId` renamed to `GroupID` in every file family.
- Equity files: `RWLavel` renamed to `RWLabel` (normalised to the spelling
  used by all other classes; interpretation of the correction request).
- EQGAMMA / FXGAMMA / IRGAMMA: `RiskValue` is a plain numeric scalar;
  `BucketCode` is the plain string `SINGLE` (no list wrapping). EQGAMMA
  `RWLabel` is likewise a plain string (e.g. `5_SPOT`).
- IRVEGA: `RiskValue` reshaped from a flat 25-element list to a nested
  5x5 list, option-expiry (BucketCode) outer, underlying tenor
  (BucketCode2) inner. `RWLabel` remains a flat 25-element list.
- Delta and vega files otherwise keep their list-valued columns
  (including EQDELTA's single-element lists) - unchanged as not covered
  by the correction request.
- `convert_to_parquet.py` updated to handle mixed scalar/list columns.

# Sector classification (added 2026-07-14)

- `REF_UNIVERSE` / `REF_MARKET_DATA` (equity): `Sector` column — GICS-style
  (11 sectors + `Index`); named tickers mapped individually, synthetic
  small caps assigned a seeded random sector.
- `REF_CSR_UNIVERSE` / `REF_CSR_MARKET_DATA` (credit): `SectorName` /
  `Sector` column — readable labels (Sovereign, Local Government,
  Financials, Basic Materials & Energy, Consumer, Technology & Telecom,
  Health Care & Utilities, Covered Bonds, Credit Index IG/HY) alongside
  the internal `Sector` code in the universe.
- Descriptive metadata only: FRTB buckets encode CRR sector *groups*
  (assigned independently) and are unchanged — no RWLabels or
  sensitivities were touched. The GICS-style sector is finer-grained than
  the CRR grouping, so several sectors map into one equity bucket.
